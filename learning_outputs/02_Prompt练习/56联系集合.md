## 案例 2：客服工单流程拆解

### 任务类型

流程拆解

### 材料

```text
业务场景：电商平台客服工单处理流程

背景：
某电商平台每天约收到 800-1200 条客服工单，来源包括 App 在线客服、电话转写、邮件和售后表单。当前客服团队共有 18 名一线客服、4 名二线客服、2 名客服主管。工单主要类型包括物流咨询、付款异常、退款申请、账号问题、商品质量投诉和发票问题。

当前系统：
1. 工单系统：记录客户问题、客户 ID、订单号、处理状态、处理人和处理结果。
2. 订单系统：查询订单状态、付款状态、发货状态、退款状态。
3. 知识库：保存物流政策、退款规则、发票规则、售后标准话术。
4. CRM：记录客户等级、历史投诉、历史购买金额。

当前 As-Is 流程：
1. 客户提交问题。
2. 工单系统自动生成工单，状态为“待分配”。
3. 一线客服人工阅读工单内容。
4. 一线客服根据经验判断工单类型和优先级。
5. 一线客服手动查询订单系统或 CRM。
6. 一线客服到知识库搜索相关政策。
7. 一线客服手写回复内容。
8. 如果涉及退款、投诉、付款异常或高价值客户，一线客服自行判断是否升级二线。
9. 二线客服处理复杂问题，必要时请主管确认。
10. 客服回复客户并关闭工单。

当前痛点：
1. 工单分类不稳定，不同客服判断标准不同。
2. 新客服查找知识库耗时较长，平均每单需要 4-8 分钟。
3. 付款异常、退款争议、投诉类工单如果未及时升级，容易造成客户不满。
4. 高价值客户没有明显提醒，可能被当作普通客户处理。
5. 回复内容质量不稳定，有时会出现过度承诺，例如承诺一定退款或承诺具体到账时间。
6. 主管只能事后抽查，无法实时发现高风险工单。

期望 To-Be 方向：
1. Agent 在工单创建后自动识别工单类型、优先级和风险等级。
2. Agent 根据工单内容判断是否需要查询订单、CRM 或知识库。
3. Agent 自动检索知识库，生成带引用来源的回复草稿。
4. 付款异常、退款争议、投诉、高价值客户相关工单必须提示人工确认。
5. Agent 只能生成建议和草稿，不能自动退款、不能自动关闭高风险工单、不能直接发送正式回复。
6. 所有分类、检索、工具调用和人工确认结果都需要记录日志。

成功指标：
- 工单初步分类准确率达到 85% 以上。
- 高风险工单转人工命中率达到 95% 以上。
- 一线客服平均处理时间降低 30%。
- 回复草稿必须引用知识库来源。
- 禁止出现自动承诺退款、赔偿或具体到账时间。

请基于以上材料拆解当前 As-Is 流程、识别痛点、设计 To-Be 流程，并说明 AI Agent 可以介入哪些节点、哪些节点必须人工确认。
```
